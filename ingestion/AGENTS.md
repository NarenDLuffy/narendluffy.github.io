# Ingestion rules

- Rooms are one per (online|offline, cell colour) across ALL schedule files, merged in ingestion/room_resolver.py; names come from any file (colour legend above a table, one-room table headings) and never create a column alone; explicit “Main session”/“RAN1 #N commences” marks Main — no chair names, room counts or positions are hard-coded.
- A name-only room is folded into the coloured room whose schedule clearly agrees with it (same date, overlapping time, same or parent/child agenda; name similarity lowers the bar but never merges alone) — the same room is often named differently across chair files.
- Schedule times are never invented: a block splits only when items have stated minutes that fit; otherwise it stays one block listing its items (stated minutes kept, mismatch noted). Same-slot claims from several files resolve to the most detailed, chairs' own tables ranked above copies of the shared grid.
- Schedule ancestry and specificity normalize terminal `.x` to the branch through canonical_schedule.is_descendant; block parsing shares this rule — explicitly timed children replace wildcard containers without counting parent minutes twice.
- Schedule blocks with only a topic name get their agenda code from chair-notes agenda titles via ingestion/topic_agenda_mapper.py (group prefixed, hyphen words split, codes of touching same-head blocks excluded), linked only on a unique match — so agenda filters catch them without guessing.
- "|" in a cell closes the open head; a timed tag whose items don't fill it ("NTN-NR (40)" + ".9.5 (20)" under "R20 (60)") is an item, not a sub-head.
- DOCX schedule ingestion reads only active visible Word runs: highlighted and inserted text stays, while deleted, hidden, and struck-through text is excluded — withdrawn agenda items must never enter the canonical schedule.
- Any time span a schedule document fills in a room but the published timetable leaves empty blocks the publish (ingestion/live.py coverage_gaps → validator) — a dropped item must never go out silently; vertical-merge continuation rows are never re-read, because Word drops their lane colour.
- Every parsed block records its table cell (SessionSourceRef.cell); ingestion/live.py cell_checks refuses one cell in two rooms and the same agenda item in two rooms at once unless one document lists it in two cells — catches Word merge/colour quirks without pictures.
- Schedule granularity: live.granularity_checks flags any published block a schedule document splits more finely (status page + Verify data); ingestion/audit_granularity.py sorts them into known causes — fix the general parse rule with a test from the real cell, never one cell by name.
- Block parsing reads ranged heads "(a-b)" (items' minutes must sum inside the range) and bare top-level codes only at the start of a timed item line; a whole block whose minutes don't add up ranks below any document's tiling.
- Tables that tile the same items at different times are a disagreement, not lost detail: canonical notes "Another schedule table lists…" on the kept blocks and granularity_checks ignores parts naming other items.
- The unqualified main “RAN1#… online and offline schedules” shared grid owns every room's outer session times and all lunch/coffee breaks. Other files, and one-room detail tables inside the main file, may only split those slots with stated detail; their different outer times, rooms, or lunch slots never create canonical blocks.
- Latest-change rule (ingestion/revision_diff.py): each block's introducedAt is when its content first appeared in its own document family (walk back through older revisions, times from docProps/core.xml, signatures cached in edit-history.json); within the main grid's authoritative time/room frame, same-slot and overlap ranking put the freshest edit before file counts — stale copies in other chairs' files must not out-vote an edit. Unknown ("", first release) falls back to the older rules.
- A timed work-area tag ("6GR (90)") under an open chair head is a sub-head, not an item, when the items below it fit its minutes — otherwise the head's time is counted twice and the block never splits. A different timed work-area head starts a new section even when the previous head's minutes are misstated; when all item minutes exactly tile the cell, they override inconsistent head totals. Overlapping canonical blocks in one room always refuse the publish.
- generate_schedule.revision_downgrades refuses a rebuild that reads an older revision (or drops a document family) than the published schedule — after the meeting the final files vanish from Meetings Sync and the meeting folder only has early ones. On meeting days the refusal is skipped: Meetings Sync is live, so a removed revision was withdrawn and must not freeze updates.
- A chair's tagged copy ("… - v02_hh3") is one revision family per tag, ordered by version then tag number; a one-room table's room may be a trailing bracket after its session label ("…Brk#2 Session (BMO 214-215)").
- Working groups live in ingestion/groups.py; RAN2 (single_grid) reads one week-grid DOCX per meeting (newest R2_<n>_Schedule_vNN from the phase's folders) via ingestion/ran2_schedule.py — splits only at chair-written "@" times, overlaps/unreadable times go to PROBLEMS and block the publish, never trimmed silently.
- RAN2 only (ingestion/ran2_topics.py): name-only schedule blocks and tagged draft folders ("[AIoT]") resolve to agenda codes via alias → agenda-title patterns, unique match only; RAN1 never uses these aliases. In the app, a parent block (10.8) matches followed leaves (10.8.1) for every group — leaf-only selection would otherwise hide it.
- A timed item followed by timed descendants that fill exactly its minutes (".10.8 Sensing (50) / 10.8.3 (50)"), or a named item followed by codes filling it ("A-IoT Phase2 (60) / 9.3.3 (60)"), is replaced by those children and its minutes are counted once.
- Untimed code lines under a timed head ("TEI, AI 7/8.1 (40) / 7 … / 11 …") are that block's agenda items (no split); a same-slot claim listing a superset of the main grid's items adds them. A code-led timed line longer than the open head's remainder starts its own block, and a code-led head is its own item. Short uncovered pieces of a main-grid slot stay visible (ranked last) so a disagreeing table never leaves a hole.
- A fresh chair-owned complete retiling may include a timed segment listing several agenda items; do not require atomic blocks for own-table detail. `granularity_checks` must flag a fresh, gapless, same-table retiling that the canonical output drops, while partial or stale disagreements remain notes.
- RAN3 (chair_notes_plus_sheet, ingestion/ran3_schedule.py): Main comes from the last weekday table of the newest Chairs_Notes DOCX (ordered by the file's date-time); rows without a written time are bounded by neighbouring rows, else PROBLEMS; "Offline" lines go to a parallel 6G offline lane. Offline rooms come from the newest Offline_meeting_room XLSX (sheet per day, trailing "(TAG)" names the room, equal consecutive slots merge). Its own topic matcher; RAN1/RAN2 rules unaffected.
- RAN3 comebacks (ingestion/ran3_comebacks.py): pink “CB: # n_Name” lines under an agenda heading link that item to the Drafts folder “CB # n_Name” by name (number only breaks ties, unique match only); pink marks the line, the “CB:” text alone means open — chairs close a CB by deleting “CB:”. Comebacks missing from newer notes stay as removed (comebacks.json).
